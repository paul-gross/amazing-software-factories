# Rubric v1

Places a measured software repository in one of three tiers from two point totals. Implemented in
[asf/rubric.py](../asf/rubric.py).

## Gates: what the repository is configured to refuse

| Signal | Points |
| --- | --- |
| Pull-request workflows run tests | 2 |
| Pull-request workflows run a linter | 1 |
| Pull-request workflows run a type check | 1 |
| Boundaries enforced by a tool (dependency-cruiser, eslint boundaries, import-linter, ast-grep, cargo-deny, denied clippy warnings, ArchUnit, knip or madge) | 1 each, at most 2 |
| Strict typing configured | 1 |
| Test code at least 0.8× the source / at least 0.4× / under 0.15× | 2 / 1 / −1 |

"Configured" is read from workflow and config files. Whether a check actually blocks a merge is not proven.

## Health: whether the refusals are working

| Signal | Points |
| --- | --- |
| Main-branch CI green, of at least 10 judged runs: 80%+ / 50%+ / under 30% | 2 / 1 / −2 |
| Largest source file: up to 100 KB / over 500 KB / over 1 MB | 1 / −1 / −2 |
| 10th-largest source file over 200 KB | −1 |

Green counts runs that finished with a verdict. Cancelled and skipped runs are reported, not judged. Source excludes
tests, generated and vendored code, fixtures, vectors and migrations.

## Tiers

- **Gated and holding:** gates 6 or more, and health 1 or more.
- **Gated, under strain:** gates 6 or more with health below 1, or gates 4–5 with health 1 or more.
- **Lightly gated:** everything else.

## Deliberately not scored

- **Rework and checkpoint vocabulary in commit subjects:** fast iteration and repair look alike from commit messages.
- **Pushing without pull requests:** a workflow choice, not a defect.
- **Conventional-commit formatting:** cosmetic.
- **Stars:** attention, not engineering.
